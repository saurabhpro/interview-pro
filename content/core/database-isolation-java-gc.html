Database isolation + Java GC: interview card

Isolation

QuestionShort answer
Dirty read?Read another transaction's uncommitted write.
Non-repeatable read?Re-read the same row and see a committed change.
Phantom?Re-run a predicate query and see rows appear/disappear.
Read committed?Each statement sees committed data at its own start; later statements may see changes.
Repeatable read?Transaction-level stable snapshot in MVCC systems; write conflicts still matter.
Serializable?Equivalent to one-at-a-time execution; expect aborts and retries.
Booking invariant?Atomic conditional decrement + unique idempotency key + short transaction.

GC

SignalLikely question to ask
High allocation rateWhich endpoint/batch allocates? Can object lifetime or batching be reduced?
Old generation keeps growingWhat reference retains objects? Inspect caches, queues, listeners, ThreadLocals.
Long pauses, low live setPause cause, heap sizing, humongous objects, collector choice, CPU pressure?
G1 vs ZGCG1 for balanced throughput/pause goals; ZGC when very low pauses dominate and overhead is measured acceptable.

Primary references: PostgreSQL transaction isolation and Oracle Java 25 garbage collectors.
